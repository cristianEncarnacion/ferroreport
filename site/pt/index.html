Contra o JasperReports 7.1.1, com os templates convertidos para JRXML 7 nos dois motores: a frio, de 198× a 234× mais rápido nos relatórios pequenos; a quente, de 2,6 a 3,7×; um milhão de linhas em 15,95 s e 18 MiB contra 62,95 s e 1.721 MiB.

Em resumo: em um relatório pequeno, a maior parte do tempo do JasperReports vai para iniciar a JVM e compilar o template. É por isso que a diferença é de duas ordens de grandeza quando um processo inicia por relatório, e de 3 a 5× quando não. Os PDFs também costumam ser menores: 1,2 MB em vez de 4,5 MB para as 20.000 linhas, e mais ou menos o mesmo tamanho com um milhão.

Feito para ser rápido, pequeno e seguro

Um motor de relatórios para qualquer stack, e um substituto direto para os templates do JasperReports que você já tem.

Idêntico pixel a pixel

Cada relatório de teste é gerado pelos dois motores e comparado pixel a pixel: métricas de texto, quebras de linha, quebras de página, grupos e variáveis seguem o Jasper exatamente.

Seguro com qualquer template

Sem desserialização de .jasper, sem código Java nas expressões, sem rede. Imagens e sub-relatórios só são carregados dos diretórios que você permitir, e limites de páginas e de tempo param um relatório que sai do controle. Cada mudança é testada contra milhares de templates danificados.

Memória constante em qualquer tamanho

As linhas são lidas conforme o relatório precisa delas e cada página é escrita assim que fica pronta. Um milhão de linhas e 23.810 páginas são geradas em 19 MB, incluindo valores como "página 3 de 240"; por HTTP, cada linha de dados viaja em uma linha de texto e o servidor fica em cerca de 50 MB. As pastas de trabalho do Excel também são escritas à medida que são montadas.

Um motor, qualquer linguagem

CLI, biblioteca Rust, JavaScript e WebAssembly, Python, Java (ele lê um ResultSet linha por linha), e uma API HTTP em uma imagem Docker de ~8 MB para C#, PHP, Go e as demais, com cache de templates e métricas do Prometheus. Ele inicia em milissegundos, então também serve para funções serverless.

Os recursos que você usa

Bandas que se dividem entre páginas, frames, imagens, sub-relatórios, tabelas, listas, crosstabs, todos os tipos de gráfico do JasperReports, códigos QR, DataMatrix, PDF417, EAN, UPC, Code 128, Code 39 e outros códigos de barras (barcode4j e Barbecue), imagens SVG, campos de formulário PDF, links e marcadores, texto com estilos, HTML e RTF, rotação, layouts de várias colunas, estilos condicionais.

PDF, Excel, Word, PowerPoint, OpenDocument, CSV e HTML

O mesmo template é exportado para uma pasta de trabalho .xlsx com as células, células mescladas, fontes, bordas, imagens e gráficos que o exportador do Jasper gera, para um .docx com o mesmo layout da exportação para Word do Jasper, para um .pptx com um slide por página, para .ods e .odt para o LibreOffice com o mesmo layout, para CSV, ou para uma página web que se parece com o PDF, para pré-visualizações no navegador. Excel e CSV são verificados célula por célula contra o Jasper. Os PDFs podem ter tags para leitores de tela (PDF/UA-1, verificado com o veraPDF): textos como parágrafos, imagens como figuras com sua descrição, tabelas com suas células de cabeçalho, listas como listas.

JRXML, ou um formato próprio

Os templates do Jaspersoft Studio funcionam como estão, JRXML 6 ou 7. Os novos podem ser escritos em .ferro: o mesmo relatório como uma estrutura indentada, com metade do tamanho, acessível por padrão e, se você quiser, sem coordenadas: as partes se empilham e se organizam em linhas, e o que se repete é definido uma vez. ferroreport convert converte nos dois sentidos, e ferroreport migrate verifica uma pasta inteira de templates antes de você trocar de motor. Como é o formato; o guia de migração.

Um designer no seu navegador

Cole uma amostra dos seus dados, arraste os campos para a página, defina fontes, cores, bordas e formatos de número, e veja o PDF mudar enquanto você trabalha. Ele abre e salva .ferro e .jrxml do JasperReports, e permite baixar PDF, Excel, Word e PowerPoint. Nada é enviado: o motor roda no seu computador. Abra o designer.

PDFs para arquivar e proteger

PDF/A-2 e PDF/A-3, verificados com o veraPDF a cada mudança; arquivos levados dentro do PDF, como o XML de uma fatura eletrônica; criptografia AES-256 com senha e permissões; links, âncoras e marcadores. Tudo no motor de código aberto, a partir das propriedades de template que o JasperReports já usa. Como.

Livre e de código aberto
