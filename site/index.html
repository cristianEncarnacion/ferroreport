Against JasperReports 7.1.1, with the templates converted to JRXML 7 for both engines: cold, 198× to 234× faster for the small reports; warm, 2.6 to 3.7×; a million rows in 15.95 s and 18 MiB against 62.95 s and 1,721 MiB.

In short: most of JasperReports' time on a small report is starting the JVM and compiling the template. That is why the gap is two orders of magnitude when a process starts per report, and 3 to 5× when it does not. PDFs are usually smaller too: 1.2 MB instead of 4.5 MB for the 20,000 rows, and about the same size at a million.

Built to be fast, small and safe

A report engine for any stack, and a drop-in one for the JasperReports templates you already have.

Pixel-identical

Every test report is rendered by both engines and compared pixel by pixel: text metrics, line breaks, page splits, groups and variables follow Jasper exactly.

Safe with any template

No .jasper deserialization, no Java code in expressions, no network. Images and subreports only load from directories you allow, and page and time limits stop a report that runs away. Every change is tested against thousands of damaged templates.

Flat memory at any size

Rows are read as the report needs them and each page is written as it is finished. A million rows and 23,810 pages render in 19 MB, values like "page 3 of 240" included; over HTTP the rows travel one per line and the server stays at about 50 MB. Excel workbooks are written as they are made too.

One engine, any language

CLI, Rust library, JavaScript and WebAssembly, Python, Java (it reads a ResultSet row by row), and an HTTP API in an ~8 MB Docker image for C#, PHP, Go and the rest, with a template cache and Prometheus metrics. It starts in milliseconds, so it suits serverless functions too.

The features you use

Bands that split across pages, frames, images, subreports, tables, lists, crosstabs, every JasperReports chart type, QR codes, DataMatrix, PDF417, EAN, UPC, Code 128, Code 39 and other barcodes (barcode4j and Barbecue), SVG images, PDF form fields, links and bookmarks, styled, HTML and RTF text, rotation, multi-column layouts, conditional styles.

PDF, Excel, Word, PowerPoint, OpenDocument, CSV and HTML

The same template exports to an .xlsx workbook with the cells, merges, fonts, borders, images and charts Jasper's exporter gives, to a .docx laid out like Jasper's Word export, to a .pptx with a slide per page, to .ods and .odt for LibreOffice laid out the same way, to CSV, or to a web page that looks like the PDF for previews in a browser. Excel and CSV are checked cell by cell against Jasper. PDFs can be tagged for screen readers (PDF/UA-1, checked with veraPDF): texts as paragraphs, pictures as figures with their description, tables with their header cells, lists as lists.

JRXML, or a format of its own

Templates from Jaspersoft Studio work as they are, JRXML 6 or 7. New ones can be written in .ferro: the same report as an indented outline, half the size, accessible by default, and with no coordinates if you like: parts stack and sit in rows, and what repeats is defined once. ferroreport convert goes both ways, and ferroreport migrate checks a whole folder of templates before you switch. How it reads; the migration guide.

A designer in your browser

Paste a sample of your data, drag its fields onto the page, set fonts, colors, borders and number formats, and watch the PDF change as you go. It opens and saves .ferro and JasperReports .jrxml, and downloads PDF, Excel, Word and PowerPoint. Nothing is uploaded: the engine runs on your computer. Open the designer.

PDFs to archive and protect

PDF/A-2 and PDF/A-3, checked with veraPDF on every change; files carried inside the PDF, such as the XML of an electronic invoice; AES-256 encryption with a password and permissions; links, anchors and bookmarks. All in the open-source engine, from the template properties JasperReports already uses. How.
