Contra JasperReports 7.1.1, con las plantillas convertidas a JRXML 7 para los dos motores: en frío, de 198× a 234× más rápido con los reportes pequeños; en caliente, de 2.6 a 3.7×; un millón de filas en 15.95 s y 18 MiB contra 62.95 s y 1,721 MiB.

En resumen: en un reporte pequeño, casi todo el tiempo de JasperReports se va en arrancar la JVM y compilar la plantilla. Por eso la diferencia es de dos órdenes de magnitud cuando arranca un proceso por reporte, y de 3 a 5× cuando no. Los PDF además suelen pesar menos: 1.2 MB en vez de 4.5 MB con las 20,000 filas, y más o menos lo mismo con un millón.

Hecho para ser rápido, pequeño y seguro

Un motor de reportes para cualquier stack, y un reemplazo directo para las plantillas de JasperReports que ya tienes.

Idéntico píxel por píxel

Cada reporte de prueba se genera con los dos motores y se compara píxel por píxel: las medidas del texto, los saltos de línea, los cortes de página, los grupos y las variables siguen exactamente a Jasper.

Seguro con cualquier plantilla

Sin deserializar archivos .jasper, sin código Java en las expresiones, sin red. Las imágenes y subreportes solo se cargan de las carpetas que permites, y los límites de páginas y de tiempo detienen un reporte que se desboca. Cada cambio se prueba contra miles de plantillas dañadas.

Memoria plana a cualquier tamaño

Las filas se leen a medida que el reporte las necesita y cada página se escribe apenas se termina. Un millón de filas y 23,810 páginas se generan en 19 MB, incluidos valores como "página 3 de 240"; por HTTP las filas viajan una por línea y el servidor se queda en unos 50 MB. Los libros de Excel también se escriben a medida que se generan.

Un motor, cualquier lenguaje

CLI, librería de Rust, JavaScript y WebAssembly, Python, Java (lee un ResultSet fila por fila), y una API HTTP en una imagen Docker de ~8 MB para C#, PHP, Go y los demás, con caché de plantillas y métricas de Prometheus. Arranca en milisegundos, así que también sirve para funciones serverless.

Lo que usas

Bandas que se dividen entre páginas, frames, imágenes, subreportes, tablas, listas, crosstabs, todos los tipos de gráfico de JasperReports, códigos QR, DataMatrix, PDF417, EAN, UPC, Code 128, Code 39 y otros códigos de barras (barcode4j y Barbecue), imágenes SVG, campos de formulario PDF, enlaces y marcadores, texto con estilos, HTML y RTF, rotación, varias columnas, estilos condicionales.

PDF, Excel, Word, PowerPoint, OpenDocument, CSV y HTML

La misma plantilla se exporta a un libro .xlsx con las celdas, celdas combinadas, fuentes, bordes, imágenes y gráficos que da el exportador de Jasper, a un .docx armado como el Word que exporta Jasper, a un .pptx con una diapositiva por página, a .ods y .odt para LibreOffice armados de la misma forma, a CSV, o a una página web que se ve como el PDF, para vistas previas en el navegador. Excel y CSV se comparan celda por celda con Jasper. Los PDF se pueden etiquetar para lectores de pantalla (PDF/UA-1, verificado con veraPDF): los textos como párrafos, las imágenes como figuras con su descripción, las tablas con sus celdas de encabezado, las listas como listas.

JRXML, o un formato propio

Las plantillas de Jaspersoft Studio funcionan tal cual, JRXML 6 o 7. Las nuevas se pueden escribir en .ferro: el mismo reporte como un esquema con sangría, de la mitad del tamaño, accesible por defecto, y sin coordenadas si quieres: las partes se apilan y se ponen en filas, y lo que se repite se define una vez. ferroreport convert pasa de uno a otro, y ferroreport migrate revisa una carpeta entera de plantillas antes de que cambies de motor. Cómo se lee; la guía de migración.

Un diseñador en tu navegador

Pega una muestra de tus datos, arrastra sus campos a la página, elige fuentes, colores, bordes y formatos de número, y mira cómo cambia el PDF mientras trabajas. Abre y guarda .ferro y .jrxml de JasperReports, y descarga PDF, Excel, Word y PowerPoint. No se sube nada: el motor corre en tu computadora. Abre el diseñador.

PDF para archivar y proteger

PDF/A-2 y PDF/A-3, verificados con veraPDF en cada cambio; archivos dentro del PDF, como el XML de una factura electrónica; cifrado AES-256 con contraseña y permisos; enlaces, anclas y marcadores. Todo en el motor de código abierto, con las propiedades de plantilla que ya usa JasperReports. Cómo.
