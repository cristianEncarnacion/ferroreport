ferroreport y las alternativas

ferroreport es un motor de reportes: entran filas y salen documentos, muchos, iguales cada vez. Lee las plantillas JRXML de JasperReports sin JVM y escribe PDF, Excel, Word, PowerPoint, OpenDocument, CSV y HTML. Las herramientas de abajo son con las que se suele comparar. Hacen trabajos distintos, así que la correcta depende de lo que haces; esta página dice dónde encaja cada una, también dónde no encaja ferroreport. Lo que dice de los otros proyectos sale de sus propios sitios y repositorios, listados en Fuentes (leídos en noviembre de 2026). La velocidad solo se da para ferroreport frente a JasperReports, tal como se midió en el README; los demás no se midieron.

JasperReports

La librería de reportes de Java que ferroreport sigue, con licencia LGPL-3.0: plantillas JRXML diseñadas en Jaspersoft Studio, compiladas y llenadas desde una fuente de datos, con exportadores a PDF, HTML, Excel, Word, PowerPoint, OpenDocument, RTF, CSV, XML y texto. Tiene un largo historial en producción, una comunidad grande, y Jaspersoft Studio y Server a su alrededor.

Frente a él, ferroreport genera las mismas plantillas sin JVM y da las mismas páginas, píxel por píxel, en cada plantilla de prueba comparable de su repositorio. El README lo mide unas 200 veces más rápido arrancando en frío (una factura de 2 páginas: 2.90 s y 195 MiB con JasperReports 6.20.6, 11 ms y 18 MiB con ferroreport) y de 3 a 5 veces más rápido que una JVM ya caliente (esa factura: 9.0 ms frente a 2.8 ms), y un millón de filas en 17.91 s y 18 MiB frente a 79.77 s y 1,731 MiB. Las plantillas no pueden ejecutar código: las expresiones salen de una lista cerrada y nada se deserializa. No ejecuta scriptlets ni clases Java tuyas, no carga archivos .jasper, no escribe XLS, RTF, XML ni texto, y no tiene servidor de reportes. La guía de migración explica cómo pasar un proyecto.

OpenPDF

Una librería de Java para archivos PDF, con licencia MPL-2.0 o LGPL-2.1 (o posterior): su núcleo es un fork de iText hecho en 2016, antes de que iText cambiara de licencia, y su módulo openpdf-html, un fork de Flying Saucer con licencia solo LGPL-2.1, genera PDF desde HTML y CSS. El documento se arma en código (párrafos, tablas, imágenes, fuentes) o como HTML. Desde la rama 2.1 necesita Java 21. Las distribuciones 6.20.6 y 7.1.1 de JasperReports escriben sus PDF con una compilación de OpenPDF hecha por Jaspersoft.

Elígelo para armar PDF desde código Java. Elige ferroreport cuando los documentos son reportes (bandas, grupos, totales, “página X de Y”, crosstabs, gráficos) que alguien diseña en vez de programar, cuando necesitas Excel o Word desde la misma plantilla, o cuando ya tienes JRXML.

OpenHTMLtoPDF con Thymeleaf

OpenHTMLtoPDF convierte XHTML bien formado (y algo de HTML5) con CSS 2.1 en PDF o imágenes, en Java, con licencia LGPL-2.1 o posterior. No soporta flexbox ni grid. El último release del repositorio original es 1.0.10 (septiembre de 2021); un fork de la comunidad lo continúa (1.1.8, abril de 2024). Se suele combinar con Thymeleaf (Apache-2.0), un motor de plantillas de Java, para poner los datos en la página.

Elígelo cuando tu equipo escribe HTML y CSS y los documentos son como páginas (cartas, recibos, facturas sencillas). Elige ferroreport para reportes cuyas páginas dependen de los datos: grupos que empiezan página nueva, encabezados repetidos en cada página, totales acumulados y por página, valores que solo se conocen al final, crosstabs y gráficos, que en HTML programas tú; y cuando quieres hojas de cálculo o Word desde la misma plantilla.

iText 8

Una librería de PDF para Java y .NET (C#) que crea PDF y modifica los existentes (dividir, unir, llenar formularios), con licencia AGPL-3.0 o una licencia comercial; con la AGPL, el software hecho con ella debe publicarse con los mismos términos. Su complemento pdfHTML, con la misma doble licencia, convierte HTML y CSS en PDF y PDF/A. iText Core 9 es ahora la versión mayor actual, con las mismas licencias.

Elígelo para manipular PDF (formularios, edición, unir archivos) con licencia comercial, o en un proyecto AGPL. Elige ferroreport para generar reportes desde plantillas con licencia MIT o Apache-2.0, con PDF/A, PDF/UA, cifrado y firmas en el motor de código abierto, y otros formatos además de PDF.

Typst

Un sistema de composición tipográfica escrito en Rust, con licencia Apache-2.0: los documentos se escriben en el marcado de Typst, que trae un lenguaje de scripting, y se compilan a PDF, PNG o SVG; la exportación a HTML es experimental, va detrás de una opción y aún no es para producción. Su empresa se fundó en Berlín en 2023, y tiene una comunidad y un ecosistema de paquetes (Typst Universe). Compone el texto mejor que un motor de reportes (párrafos, división de palabras, fórmulas).

Elígelo para documentos que escriben personas: artículos, libros, cartas, documentación técnica. Elige ferroreport para reportes de datos (bandas, grupos, variables, valores tardíos, un millón de filas con memoria plana), para hojas de cálculo y documentos de Word, y para reutilizar JRXML. En Typst la lógica del reporte la programas tú.

Carbone

Un generador de reportes para Node.js cuyas plantillas son documentos de oficina (DOCX, ODT, XLSX, ODS, PPTX...) hechos en Word o LibreOffice, con etiquetas como {d.nombreEmpresa} donde van los datos JSON. Escribe PDF, DOCX, XLSX, ODT, PPTX, ODS, XML y CSV; el PDF y la conversión a otro formato pasan por un conversor (LibreOffice; la versión 5 también puede usar Chrome u OnlyOffice). La Community Edition tiene el código disponible bajo la Carbone Community License, que no permite ofrecerla a otros como servicio alojado de generación de documentos, y va una versión mayor por detrás de la Enterprise Edition de pago.

Elígelo cuando la gente de negocio diseña las plantillas en Word o LibreOffice. Elige ferroreport cuando las plantillas salen de Jaspersoft Studio o se escriben como texto, cuando quieres una licencia aprobada por la OSI (MIT o Apache-2.0), PDF sin tener una suite de oficina instalada, o el modelo de bandas y grupos de JasperReports.

Apache POI y FastExcel, para hojas de cálculo

Apache POI (Apache-2.0) es la librería de Java para los formatos de Microsoft Office: lee y escribe XLS y XLSX, escribe archivos XLSX muy grandes con su API SXSSF, que va escribiendo las filas, y lee y escribe archivos de Word y PowerPoint con menos cobertura. FastExcel (Apache-2.0) es una librería de Java que escribe XLSX con poca memoria y estilos básicos, todavía sin gráficos, y lee el contenido de las celdas de un XLSX. Las dos arman el libro en código, celda por celda.

Elígelas para hojas de cálculo que son más datos que diseño, o para leer y cambiar libros existentes. Elige ferroreport cuando la hoja de cálculo es un reporte: la misma plantilla da el PDF y el libro, armado como el del exportador de JasperReports (celdas combinadas, fuentes, bordes, imágenes, gráficos como imágenes) y escrito a medida que se hace. ferroreport no lee libros de Excel y no escribe XLS.

Dónde ferroreport se queda atrás

  • Madurez. Su primera versión estable, la 1.0.0, salió en noviembre de 2026, y la actual es la 1.4.0. JasperReports, iText, Apache POI y OpenPDF llevan mucho más tiempo en producción.
  • Comunidad. Mucho más pequeña que la de JasperReports, iText, Apache POI o Typst: menos gente que responda preguntas, menos artículos, menos integraciones.
  • Componentes Java propios. Nunca ejecuta código Java: ni scriptlets, ni métodos estáticos tuyos en expresiones, ni componentes personalizados, mapas, customizers ni temas de gráficos, ni jars de extensiones de fuentes. Las plantillas que dependen de eso necesitan cambios (cómo).
  • Herramientas. No tiene servidor de reportes, visores ni tableros, y su diseñador en el navegador es una primera versión (campos, textos, formas, imágenes, estilos; aún sin gráficos, tablas ni grupos). Jaspersoft Studio sigue sirviendo para sus plantillas.
  • Cobertura. No escribe XLS, RTF, XML ni texto; formatos de números y fechas solo para en_US, español, francés, portugués, italiano y alemán; solo consultas SQL (no HQL, XPath ni MDX), en PostgreSQL, MySQL y MariaDB, SQL Server y SQLite; no lee ni edita PDF ni libros de Excel existentes.

Lo que está soportado y lo que todavía no está en la tabla de compatibilidad, y ferroreport doctor te da la respuesta para una plantilla.

Fuentes

  • JasperReports: repositorio (licencia, descripción, formatos de exportación); los exportadores y la compilación de OpenPDF son los de los jars de JasperReports 6.20.6 y 7.1.1 con los que se prueba este proyecto.
  • OpenPDF: repositorio (licencias, módulos, versión de Java, historia del fork).
  • OpenHTMLtoPDF: fork de la comunidad y repositorio original (licencia, CSS, releases). Thymeleaf: repositorio (licencia).
  • iText: iText Core (versiones, lenguajes, licencias) y el repositorio de pdfHTML (licencia, HTML a PDF y PDF/A).
  • Typst: repositorio (licencia, lenguaje), formatos de exportación, exportación a HTML, acerca de.
  • Carbone: repositorio (plantillas, formatos, conversores, ediciones) y su licencia.
  • Apache POI: componentes, hojas de cálculo y SXSSF, aviso legal.
  • FastExcel: repositorio y su licencia.
  • ferroreport: README (qué soporta, rendimiento) y CHANGELOG (en inglés).
